# Cursor Background Task 研究与 zdsh 实现方案

研究日期：2026-10-23。范围是 Agent 发起的本地后台 shell 命令，不是云端 Background Agent。

**状态：REA 研究与首版实现完成，编译检查通过；交互验证由用户进行。** 命令通过现有审批后，在新的 Terminal Tab 中运行；Agent 可以继续处理其他工作；命令结束后，将结果交给发起任务的 Agent。下文区分 Cursor 安装包证据、改造前的 zdsh 源码审计与本次实现。

## 核心结论

Cursor 将后台命令拆成执行句柄、终端展示和会话完成通知三个部分。前台转后台时移交同一个进程、输出流和取消句柄，不重新运行命令。完成通知按会话排队，Agent 空闲后启动专门的后续回合；Agent 正在生成、等待审批或等待回答时不会被通知打断。

改造前的 zdsh 已有真实 PTY、命令审批、sandbox、Terminal Tab 和任务状态展示。主要缺口是独立的后台任务所有者，以及会话层的完成通知队列。仅将当前工具等待过程改成 `detach()` 不够：原终端 handle 释放会终止进程，直接发送完成消息又会中断 Agent 当前回合。

Cursor 的可见后台终端是输出镜像，是否创建受功能开关控制，完成后会关闭镜像并保留日志。zdsh 按用户要求创建真实 Terminal Tab，并保留完成后的输出，是明确的产品选择。

## Cursor 执行行为

### 进入后台

已确认三条入口，见证据 E：

1. 支持相应参数的工具版本中，`block_until_ms=0` 或 `is_background=true` 直接后台执行。
2. 使用正的 `block_until_ms` 时，等待期限到达后把仍在运行的命令移交给后台管理器。这个期限表示前台等待时间，不表示杀死进程的超时。
3. 手动操作通过 `toolCallId` 找到正在等待的命令并请求后台化。

移交保存同一个异步迭代器、未完成的读取、PID、stdin、AbortController、开始时间和已经收集的输出。不会重新启动命令，也不会丢弃切换前的输出。

普通 Agent 的一条默认等待路径为 30 秒，BACKGROUND Agent 为 10 分钟；配置和工具版本可以覆盖这些值。静态代码中还存在 24 小时硬超时，但只确认传入前台执行及移交路径，不能泛化为所有直接后台任务的上限。

后台执行沿用命令权限、管理员 denylist 和 sandbox 检查；后台化不绕过审批。

### 进程与终端

执行器管理真正的进程和输出流，终端 provider 用伪终端镜像同一份输出。可见镜像只将 Ctrl-C 转换为取消操作，普通输入不直接发给进程；stdin 由另一条 API 控制。

`disable_terminal_output_ui_streaming` 开关为 true 时，登记 headless work；其他分支立即创建 `hideFromUser:false` 的终端。元数据包含 `backgroundShellId`、`conversationId` 和 `agentOwned`。没有读取用户账号的运行时开关，因此不能说 Cursor 在所有环境下都会创建可见 Tab。

打开后台任务时，有镜像终端就显示它；headless 路径打开保存的输出文件。完成后终端 provider 发布完成事件并关闭镜像终端，日志文件保留。

### 输出与停止

后台输出写入 `<projectDir>/terminals/<shellId>.txt`。文件头记录命令、目录、PID、标题、状态、开始时间和运行时长；约每 5 秒更新头部。结束时记录退出码、结束时间及成功、失败或中止状态。移交已有命令时，先写入切换前的输出，再追加后续输出。

输出有明确的容量和截断边界，不是无限日志。已读流处理路径分别限制 stdout/stderr，达到限制会写入截断说明；部分普通 shell 路径还会把大输出转存文件并向模型返回尾部。

Stop、关闭镜像终端和 Ctrl-C 均可沿保存的取消句柄中止任务。已确认 AbortController 链，未完整确认每个平台底层的进程组信号策略。

## Cursor 展示行为

证据 U 确认的组件和状态模型：

- shell 卡片提供 `Run in background` 提示组件，默认等待文案说明 Agent 正在等待命令。共享卡片默认延迟 5 秒展示；点击后等待后台化结果，失败可恢复操作。该组件存在及其调用逻辑已确认，但没有证明当前 Glass 运行时必然启用此提示。
- 输入区附近的 Terminal 入口显示任务数量和运行指示，点击打开任务列表。
- 列表按会话合并真实终端行与尚未被终端行表示的后台任务，使用 shell ID 去重。
- 行中显示终端图标、标题和已运行时间；点击可查看终端或日志，悬浮操作可 Stop。
- 没有任务时入口隐藏；列表默认不会自行展开，设有高度限制及更多条目入口。
- 退出界面存在按会话列出后台终端的确认组件。

这组证据来自安装包中的组件、状态组合和事件绑定，不包含运行时截图或像素测量。

## 完成后怎样通知 Agent

证据 D 确认的路径：

```text
进程结束
  → 生成带 taskId、toolCallId、conversationId 的完成事件
  → 所属会话的 pending 队列
  → 等待 Agent 空闲，且没有审批或问答阻塞
  → backgroundTaskCompletionAction
  → 追加带 BACKGROUND_TASK_COMPLETION 标记的模型上下文
  → 运行后续 Agent 回合
  → 确认消费；失败则保留或重新排队
```

完成载荷包含任务类型、成功/失败/中止状态、任务 ID、标题、可选工具调用 ID、退出码或信号详情，以及输出文件路径。通常不把整个终端输出直接塞入消息，Agent 可以按需读取日志。

该事件会真正进入模型上下文并继续运行 Agent，不只是桌面通知、toast 或修改旧工具结果。Cursor 内部将它编码为带专用原因标记的 simulated user message，要求简短说明结果和必要后续，并避免重复已经处理的结果。

队列以会话和任务身份去重，区分 pending 与 in-flight。同一会话有派发互斥；成功 ack，错误或部分取消路径重新排队，并可提供 Resume。显式等待某个任务结果时，会 suppress 后续异步通知，避免双重处理。归档会话会 mute、清理通知并停止相关唤醒。

Agent Host 可记录完成事件，客户端以 `lastEventId` 重新订阅，补发尚未唤醒的事件。该能力支持宿主仍然存活时的重新连接；已读 journal、游标和队列包含内存状态，不能据此声称整个 IDE 重启后仍保证运行中进程或未投递通知恢复。Host 自己派发和 UI 派发受所有权开关控制，不能同时实现两条无协调的唤醒路径。

## zdsh 现状

以下是当前仓库源码审计，不是 Cursor REA 结论。

| 部分 | 已有基础 | 缺口及约束 |
| --- | --- | --- |
| terminal 工具 | `terminal_tool.rs` 共用审批、sandbox、创建和等待逻辑 | 同步等待；`timeout_ms` 是终止超时，不能直接改成转后台期限 |
| 终端所有权 | `AcpTerminalHandle`、共享退出等待、退出输出缓存 | handle 释放会 release/kill；后台必须由独立管理器持有 |
| Terminal Tab | `TerminalView` 可以包装同一个 `acp_terminal.inner()`；有运行、成功、失败状态 | 需要连接 Agent 工具到新 Tab 的桥接；不能为展示再启动一次命令 |
| UI 桥接 | `SiblingThreadHost` 已有跨 agent 与 agent_ui 的模式 | 可增加对应终端展示接口，避免 crate 反向依赖 |
| Agent 续跑 | native connection 有提交、运行及保存逻辑 | `submit_native` 会中断已有回合，不能直接调用它投递完成事件 |
| 消息队列 | `ThreadView` 有跟进队列及 Stop 暂停行为 | 包含 Editor 实体，属于 UI、未持久化，不能充当任务收件箱 |
| 会话保留 | 保留运行中会话及部分空闲会话 | 现有淘汰条件不知道后台任务，需要保留原会话或按 ID 恢复投递 |
| 持久化 | DbThread 存消息和设置；终端有目录及标题元数据 | task terminal 不序列化；普通终端恢复只会启动新 shell，没有任务恢复能力 |
| 输出 | ACP 缓存结束时的当前输出，工具默认上限 16 KiB | scrollback 不是完整持久日志，长期任务需要明确日志容量策略 |

## zdsh 首版实现

实现位于 `crates/agent/src/background_task.rs`，通过 `agent.rs` 的原生会话驱动、`terminal_tool.rs` 与 `agent_ui/src/agent_panel.rs` 接入。下面是已实现的行为；运行时外观及交互仍待用户验收。

1. **复用同一条获批执行链。** 扩展现有工具的后台执行参数，区分前台等待期限和命令硬超时。支持立即后台、等待期限移交及手动转后台；默认前台等待 30 秒。工具返回任务 ID，新 Tab 使用同一个终端实体，Agent 不必等进程结束。
2. **独立持有任务。** 管理器记录原会话、工具调用、命令、时间、运行状态和取消句柄，持有原 ACP 终端及 sandbox。切换 Tab、工具返回和普通会话视图释放不能误杀任务。
3. **每个任务新建 Terminal Tab。** 使用同一个终端实体，加入右侧 Terminal 分类；不抢走当前 Agent 焦点。显示标题、运行状态、持续时间和停止操作，完成后保留输出。新增 UI 优先使用 GPUI Kit。
4. **会话层完成队列。** 结束事件先记录结果，再按原会话 ID 投递。Agent 忙碌、等待审批或 Ask Question 时排队；空闲后继续处理。人工 Stop、Debug 等待和会话删除具有明确的暂停或取消语义，不能因完成通知意外恢复用户已经停止的工作。
5. **模型能查询和停止任务。** `background_task` 按原会话列出状态、读取指定任务输出或停止任务。完成载荷明确标为系统产生的任务事件，附状态、退出码、目录和输出片段；不显示成用户亲自发送的消息。日志内容按工具数据处理。
6. **分别保存运行状态与通知状态。** 保存任务元数据、受限日志和 pending/delivered 信息，使用稳定事件 ID 去重。多个任务同时完成可合并处理。不能在模型请求是否成功不明时宣称严格 exactly-once。
7. **定义恢复边界。** IDE 重启后保存结果和历史；无法确认存活的任务标为 Interrupted，不自动重跑命令、不重新申请之前的提权。跨 IDE 进程保活需要单独的 supervisor，不属于这一版。

关闭行为：切换 Tab 不停止；关闭运行中的任务 Tab 停止任务，完成后关闭只移除展示；关闭 Agent Tab 保留后台所有权及原会话投递，永久删除会话则停止相关任务并抑制唤醒。删除前会等待已经排队的保存结束，避免旧保存重新写回被删除的会话。

本版输出策略：每个任务保存最近 64 KiB 终端内容，运行中约每 5 秒更新；完成通知携带最近 4 KiB，指定任务查询返回当前快照并指明截断。没有实现完整原始日志文件或跨 IDE 进程保活。完成结果与通知上下文在请求模型前进入同一会话保存队列；成功处理后记录 delivered，失败或用户 Stop 则暂停。查询已完成任务时，只有工具结果进入会话历史才消费通知，单纯列出状态不消费。

按用户约定，没有新增测试或自行启动应用。`cargo check --locked -p zed --bin zed` 已通过。待人工验收：成功/失败/取消、持续输出、前台转后台、Agent 忙闲切换、审批或问答阻塞、多个任务同时完成、关闭 Tab、人工 Stop 和 IDE 重启。
