# Terminal backend

The terminal entity uses the project-owned [terminal_core](../terminal_core/README.md) ANSI processor and grid model. GPUI renders the resulting cells through `terminal_view`. The existing Zed terminal entity remains the interface for terminal tabs, tasks, remote sessions, and Agent command output.

`src/warp/model.rs` owns the primary and alternate grids, parser state, cursor configuration, color overrides, and terminal events. `src/warp.rs` translates grid coordinates, cells, selection, search, and navigation into the host API. `src/warp/pty.rs` feeds PTY output into Warp and handles input, resize, child exit, and shutdown. Synchronized output is flushed on timeout and child exit.

The operating-system PTY allocation and child-process transport still come from Zed's Alacritty fork. Its terminal emulator, grid, selection, search, and rendering-cell types are not used. Keeping this transport preserves Zed's process discovery, signal-mask handling, and Windows spawning behavior without creating a second GUI application context. Non-PTY task output uses the same Warp parser.

Core protocol policy enables hyperlinks and grid storage fixes. Image rendering and Kitty keyboard negotiation are disabled. Core-owned types replace all WarpUI types; the dependency graph contains no Warp application, WarpUI, or Warp font library. Licenses and source commits are recorded in the two local core crates.

Local interactive Bash and Zsh terminals use command blocks. `src/command_blocks/shell_startup.rs` loads per-session hooks through private startup files before the first prompt, after the user’s shell configuration and toolchain activation. Zsh forwards its startup files and restores the user’s `ZDOTDIR`; Bash uses an interactive non-login process with a managed rcfile, sourcing login profiles when login startup is requested; Bash login-shell detection and logout files are not emulated. Startup files remain owned by the terminal and are removed when it is dropped. No setup commands are typed into the PTY. `src/command_blocks.rs` submits commands and sends Warp's hex-encoded Preexec and CommandFinished messages with a registered random session ID. The backend starts a fresh primary grid at command execution and captures its output, duration, directory, and exit status at shell completion. A missing completion hook leaves the exit status unknown. Completed output is retained in display-only terminal entities and bounded by the configured scrollback line budget.

The registered prompt-only `Precmd` hook carries the shell's current directory and an allowlisted `zdsh_environment` snapshot after each command. `src/prompt_context.rs` queries Git branch or detached HEAD, plus Rust, Node, and Python versions when project markers or an active Python environment apply. Queries run in the background with the reported shell environment, a two-second timeout per subprocess, cancellation on command execution, and Rust toolchain auto-installation disabled. Results are refreshed at the next prompt; failures appear in the context bar's information tooltip. No environment probe command is typed into the PTY.

The GPUI view provides an independent multiline editor, in-session command history, collapsible output, and command/output copy buttons. Enter submits the buffer, Shift+Enter inserts a line, and Up/Down browse history for single-line input. Running programs receive terminal input directly; alternate-screen applications use the full terminal surface.

Task terminals, Agent-owned terminals, embedded/read-only views, remote shells, shells other than Bash or Zsh, and custom shell arguments beyond interactive/login flags use the continuous GPUI surface with the same Warp backend. Block history is in memory and is not restored after closing the terminal. Snapshots stop at the shell completion hook and do not include later background-job output. Search and selection remain local to each terminal surface rather than spanning the command-block document.

## Completions

`src/completions.rs` adapts the project-owned [terminal_completion](../terminal_completion/README.md) engine. The core owns token parsing, embedded command signatures, matching, ranking, replacement ranges, and history matching. The adapter supplies executable names from the terminal launch environment's `PATH`, common Bash/Zsh builtins, and filesystem entries relative to the shell's current directory. Embedded signatures supply static subcommands, flags, and argument values. The shared registry initializes without Warp CLI registration or enlarged-stack initialization. File queries run on a background executor; errors other than missing paths are reported beside the input.

Completion uses the launch environment, not subsequent environment changes made inside the shell. Native shell completion functions, custom aliases/functions, and dynamic signature generators are not connected. No generator commands or user input are executed to produce suggestions. History hints use Warp's prefix matcher over commands submitted in the current terminal, preferring the newest longer match; shell history files are not imported.

Compile the terminal and view with `cargo check --locked -p terminal -p terminal_view --all-targets`. Use `./script/clippy -p terminal -p terminal_view --locked` for linting and `cargo build --locked -p zed --bin zed` for the editor binary. These commands compile targets without running tests.
